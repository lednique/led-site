# Как запустить LEDNIQUE-сайт с нуля

Инструкция для человека, который никогда не выкладывал сайты. Делайте шаги по порядку. Ничего не пропускайте.

Нужно три бесплатных аккаунта:

1. [GitHub](https://github.com) — хранилище кода  
2. [Supabase](https://supabase.com) — база карточек  
3. [Vercel](https://vercel.com) — хостинг сайта  

---

## Часть 1. Код на GitHub

1. Зарегистрируйтесь на github.com.  
2. Справа сверху нажмите **+ → New repository**.  
3. Имя: `led-site`. Репозиторий **Private** или **Public** — как удобно.  
4. **не** ставьте галочки README / .gitignore (код уже есть).  
5. На своём компьютере откройте папку проекта и в терминале выполните:

```bash
git init
git add .
git commit -m "site"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/led-site.git
git push -u origin main
```

Если проект уже в GitHub — достаточно `git push`.

---

## Часть 2. База данных Supabase

1. Зайдите на supabase.com → **Start your project**.  
2. **New project**. Придумайте пароль базы (сохраните его). Регион — ближайший.  
3. Подождите, пока проект создастся (зелёная галочка).  
4. Слева: **SQL Editor** → **New query**.  
5. Откройте файл `supabase/schema.sql` из этого проекта. Скопируйте **весь** текст.  
6. Вставьте в окно SQL Editor и нажмите **Run**. Должно быть Success.  
   Если сайт уже был настроен раньше — запустите этот файл ещё раз: он добавит realtime, хранилище картинок и поле иконки вкладки.  
7. Слева: **Project Settings** (шестерёнка) → **API**.  
8. Скопируйте два значения и сохраните в блокнот:  
   - **Project URL** (похоже на `https://abcd.supabase.co`)  
   - **anon public** ключ (длинная строка, начинается с `eyJ`)
9. Слева: **Authentication** → **Users** → **Add user** → **Create new user**.  
   Введите свою почту и пароль, поставьте галочку **Auto Confirm User** и нажмите **Create user**.

Это публичный ключ сайта: читать содержимое базы может кто угодно, а вот **запись**
разрешена только пользователю из шага 9 — именно его почтой и паролем вы входите
в панель `/admin`. Так устроено специально: раньше политики базы разрешали запись
всем, у кого есть публичный ключ, то есть изменить или удалить сайт мог любой
посетитель (см. `supabase/schema.sql` и «Безопасность» в конце этого файла).

---

## Часть 3. Хостинг Vercel

1. Зайдите на vercel.com → войти через **Continue with GitHub**.  
2. **Add New… → Project**.  
3. Найдите репозиторий `led-site` → **Import**.  
4. Framework Preset должен быть **Vite**. Менять команды не нужно.  
5. Раскройте **Environment Variables** и добавьте три строки:

| Name | Value |
| --- | --- |
| `VITE_SUPABASE_URL` | Project URL из Supabase |
| `VITE_SUPABASE_ANON_KEY` | anon public ключ |
| `VITE_ADMIN_EMAIL` | *(необязательно)* почта администратора — подставится в форму входа |
| `ADMIN_PASSWORD` | *(необязательно)* запасной вход, нужен только если сайт работает без Supabase |

Пароль для входа в панель задаётся **в Supabase** (Authentication → Users), а не на Vercel.

6. Нажмите **Deploy**. Подождите 1–2 минуты.  
7. Когда появится **Congratulations**, нажмите на ссылку вида `led-site.vercel.app`.

Если меняли переменные **после** первого деплоя: **Settings → Environment Variables**, сохраните, затем **Deployments → ⋯ → Redeploy**.

## Часть 3.1. Хостинг GitHub Pages (без Vercel)

GitHub Pages отдаёт только файлы — серверного кода (`api/*.ts`) там нет.
Сайт это переживает: регион определяется по часовому поясу браузера, вход в
панель идёт через Supabase Auth. Единственное, что требует сервера, — галерея
Google Photos; для неё есть функция в Supabase Edge Functions.

**Сайт**

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
   Сборку и публикацию `dist` делает `.github/workflows/deploy-pages.yml`.
2. **Settings → Secrets and variables → Actions → Variables** — добавьте:
   `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_ADMIN_EMAIL` (необязательно)
   и `VITE_API_BASE` = `https://<project-ref>.supabase.co/functions/v1`
   (нужен, только если делаете функцию Google Photos из пункта ниже).
3. Запушьте в `main` — деплой запустится сам (или **Actions → Deploy to GitHub
   Pages → Run workflow**). Прямые заходы на `/privacy`, `/admin` работают:
   workflow кладёт копию `index.html` в `404.html`.

**Функция Google Photos**

```bash
npx supabase login
npx supabase link --project-ref <project-ref>
npx supabase functions deploy google-photos --no-verify-jwt
```

`--no-verify-jwt` отключает проверку JWT: галерея публичная, Supabase-сессии у
посетителя нет. Код функции — `supabase/functions/google-photos/index.ts`
(та же логика, что в `api/google-photos.ts` для Vercel).

**Ключ в запросе.** В проектах на новых ключах Supabase (`sb_publishable_…`)
шлюз требует ключ на каждом запросе к функции, иначе отвечает ещё до запуска
кода:

```
401 {"code":"MISSING_CREDENTIALS","message":"No credentials found on the request…"}
```

Поэтому сайт при внешнем `VITE_API_BASE` сам добавляет заголовок
`apikey: <VITE_SUPABASE_ANON_KEY>` (см. `apiFetch` в `src/lib/api.ts`). Ключ тот
же, что нужен базе, — отдельная переменная не требуется. На Vercel заголовок не
добавляется: функции свои.

Если после смены переменных галерея всё ещё даёт 401 — проверьте, что в
`VITE_SUPABASE_ANON_KEY` лежит ключ именно этого проекта, и перезапустите
workflow (значения `VITE_*` вшиваются в сборку при билде).

## Часть 4. Панель управления

Адрес панели: `https://ВАШ-САЙТ.vercel.app/admin`

С главной страницы кнопки «panel» больше нет — адрес нужно помнить.

Вход — **почта и пароль пользователя Supabase** (Часть 2, шаг 9). Сессия сохраняется
в браузере, поэтому перезагрузка страницы не выбрасывает из панели; кнопка
**Выйти** в шапке панели её завершает.

Если Supabase не подключён (сайт работает на встроенном демо-наборе), панель
спрашивает только пароль — серверную переменную `ADMIN_PASSWORD` на Vercel или
локальную `VITE_ADMIN_PASSWORD`. Правки в таком режиме остаются только на вашем
устройстве.

В панели:

- **Карточки** — публикации. Слева превью, справа поля.  
  Включите «Английская версия», если карточка должна быть на Global.  
  Без галочки карточка видна **только** на русской версии.  
- **Баннер** — картинка слева, тексты EN / RU столбцами.  
- **Кнопки** — иконки слева, подписи на двух языках.

Картинка карточки — высокий прямоугольник. Если файл не выбран, область пустая.  
Хештег добавляется клавишей **Enter**. На сайте он заменяет надпись Article внутри статьи, на превью карточек хештегов нет.

Цвет акцента по умолчанию `#5A5A5A`.

### Что панель делает с загруженной картинкой

Файл обрабатывается только если он не влезает в лимит поля — иначе на сервер
уходят оригинальные байты, без потери качества и без смены формата.

| Поле | Что происходит с файлом |
| --- | --- |
| **Изображение в статье** (блок «+ Изображение») | Ширина до **900 px** — ровно столько занимает колонка статьи. Файл уже 900 px остаётся как есть; шире — ужимается до 900 px по ширине, высота масштабируется пропорционально. Вертикальные снимки не обрезаются: лимит только по ширине, поэтому фото 900×1350 так и лежит. |
| **Главный баннер** («Баннер» → «Изображение баннера») | **Исходное разрешение сохраняется всегда.** Ограничение — вес файла **2 МБ**: тяжёлый оригинал переносится в JPEG с максимально возможным качеством при том же размере картинки, и лишь если в 2 МБ не удалось уложиться даже на минимальном качестве — слегка уменьшается разрешение. |
| Обложка карточки, фон splash, иконки соцсетей | Длинная сторона до **1600 px**, JPEG. |
| Иконка вкладки (favicon) | Длинная сторона до **256 px**, PNG. |

GIF, APNG, анимированный WebP, SVG и ICO не перерисовываются никогда — через
canvas от анимации остался бы один кадр. Если такой файл тяжелее лимита веса
поля, панель честно попросит уменьшить его заранее.

Обрезка под макет — это CSS, а не обработка файла: баннер сайт заполняет фоном
(`background-size: cover`), а картинка статьи на телефоне растягивается от края
до края. Поэтому оригинальный размер снимка сохраняется, как бы он ни выглядел
в узкой колонке.

### Параллакс-видео в статье

В редакторе статьи нажмите **«+ Параллакс-видео»** и выберите ролик: **MP4 (H.264)**
или **WebM**, до **50 МБ**. Плеера, кнопок и звука у блока нет — кадр привязан
к прокрутке: первый кадр стоит, когда статья только открыта, последний — когда
блок целиком уходит за верхний край экрана. Кадр не обрезается: на компьютере блок
не выше **440 px** и не растягивается по ширине колонки, на телефоне идёт от
края до края экрана и показывается целиком по высоте. Звук не используется,
поэтому бессловесные ролики, нарезки и анимации подходят идеально.

Пока в статье есть такой блок, она открывается через экран загрузки — до
готовности медиа: для ролика это первый кадр, для анимации из кадров — вся
последовательность, от первого кадра до последнего (но не дольше 10 секунд:
на медленной сети статья показывается как есть).

**Ролик как файл на сайте не хранится**: панель нарезает его на кадры прямо в
браузере и загружает в корзину картинки — их Supabase берёт всегда. Нарезка
всегда выходит из **60 кадров** JPEG шириной до **1080 px** (у вертикального
или квадратного ролика кадр ужимается сильнее — см. ниже). На сайте блок
выглядит и листается так же, разница только внутри: вместо одного видеофайла
хранится последовательность кадров (`frames` у блока), а под полем загрузки
панель показывает их число. Работает панель в два прохода по 30 кадров: первый
кусок нарезали — сразу грузим, пока второй ещё перематывается, поэтому прогресс
двигается ровно и браузер не держит в памяти все картинки разом.

Кадры держатся на сайте расшифрованными — это ~4 байта на пиксель, поэтому вся
последовательность подгоняется под бюджет памяти телефона (48 Мпикс ≈ 190 МБ,
чтобы телефон не начинал выгружать вкладки). Бюджет делит память **между всеми
кадрами**, а не сокращает их: у квадратного ролика кадр выходит ~894 px, у
вертикального 9:16 — ~671×1193 px, у горизонтального 16:9 — все 1080 px.
Кадров при этом всегда 60. Меньше их только у совсем короткого ролика: если
весь он короче 2 секунд, 60 снимков приходили бы чаще, чем кадры в самом файле,
— панель берёт столько, сколько в нём есть, но не меньше 12.

APNG или анимированный WebP для такого блока не годятся: браузер проигрывает
их сам и не даёт показать конкретный кадр, то есть привязать анимацию
к прокрутке нельзя. Отдельные кадры — можно, поэтому панель делает именно их.

### Галерея из Google Photos

В редакторе статьи нажмите **«+ Галерея Google Photos»** и вставьте **ссылку общего доступа** к альбому — например, начинающуюся с `https://photos.app.goo.gl/…` или `https://photos.google.com/share/…`.

1. В Google Photos откройте нужный альбом → **Поделиться** → включите **доступ по ссылке**.
2. Скопируйте именно ссылку альбома, а не ссылку на отдельную фотографию.
3. Вставьте её в блок галереи и сохраните статью.

Сайт берёт список только из общедоступного альбома через свой `/api/google-photos` endpoint: Google-аккаунт, ключ API и OAuth не нужны и не попадают в браузер. После изменения состава альбома новые фотографии появятся при следующем открытии или обновлении статьи; CDN-кэш может задержать обновление до 5 минут. Если доступ по ссылке выключить, галерея перестанет загружаться.

Галерея занимает гибкую ширину до 800 px, фотографии идут вертикальной лентой с шагом 10 px. Каждый кадр имеет высоту 400 px на компьютере и 250 px на телефоне; широкие изображения листаются горизонтальным свайпом. Нативный pinch-to-zoom браузера не заблокирован.

## Часть 4.1. Заявки и две версии сайта

**Формы на сайте нет — ни в одной версии.** Блок **«Заявки»** показывает кнопку
с почтовым адресом: она открывает почтовую программу посетителя с готовой темой
и заготовкой письма, а под кнопкой — ссылка на Telegram. Переписка идёт в почтовом
клиенте и мессенджере посетителя, то есть **вне сайта**, поэтому сайт не собирает
персональные данные: не нужны ни серверная функция приёма заявок, ни бот, ни токены.

Адрес и ник задаются в одном месте — `src/contacts.ts`:

```ts
export const CONTACT_EMAIL = "lednique1@ya.ru"; // ← рабочий ящик оператора
export const TELEGRAM_HANDLE = "@lednique";
export const TELEGRAM_URL = "https://t.me/lednique";
```

Проверьте, что почта действительно работает: письма с сайта приходят именно на неё.
После правки файла нужен новый деплой (push в GitHub → Vercel соберёт сам).

✅ **Ящик уже российский — это правильно и менять его не нужно.** `lednique1@ya.ru`
(Яндекс Почта) хранится на территории РФ, поэтому ч. 5 ст. 18 152-ФЗ соблюдена:
первичная запись данных российского заказчика не попадает в зарубежную базу.

⚠️ **Не заменяйте его на Gmail, Outlook или iCloud.** Причина юридическая: исключения
из запрета ч. 5 ст. 18 — только пп. 2, 3, 4, 8 ч. 1 ст. 6, договорного основания
(п. 5) среди них нет. При зарубежном ящике первое же письмо российского заказчика
образует состав ч. 5 ст. 18 (штраф по ч. 8 ст. 13.11 для граждан — 30–50 тыс. ₽)
и потребует уведомления о трансграничной передаче (ст. 12).

Если захотите адрес на своём домене (например, `hello@lednique.ru`) — сделайте его
**через российскую почту** (Яндекс 360 для домена, Mail.ru для бизнеса) и впишите
сюда: юридически это то же самое, а выглядит солиднее. Подробности — в
[`docs/rkn-notifications.md`](./docs/rkn-notifications.md), раздел 2.0.

**Две версии сайта.** `api/region.ts` читает заголовок `x-vercel-ip-country`,
который Vercel добавляет к каждому запросу, и отвечает кодом региона. Отличие
версий ровно одно — блок «Соцсети»:

| Версия | Блок «Соцсети» | Заявки |
| --- | --- | --- |
| Международная | Иконки соцсетей из панели | Кнопка mailto + Telegram |
| Российская | Текстовый ник `@lednique` (ссылка на Telegram) | Кнопка mailto + Telegram |

Иконки Instagram и Facebook в российской версии не показываются: это символика
Meta Platforms Inc., деятельность которой признана в РФ экстремистской и запрещена
(ч. 1 ст. 20.3 КоАП РФ). Если страну определить не удалось, показывается российская
версия — так осторожнее.

**Предпросмотр версий.** Добавьте к адресу `?region=ru` или `?region=global` —
выбор запомнится в браузере; `?region=auto` вернёт определение по IP. В локальной
разработке версия задаётся переменной `VITE_DEV_REGION` (по умолчанию `ru`);
проверить определение по стране можно так:
`curl -H "x-vercel-ip-country: US" http://localhost:5173/api/region` → `global`.

**Почему так сделано.** С 1 июля 2025 года ч. 5 ст. 18 152-ФЗ запрещает первичный
сбор персональных данных граждан РФ в базы за пределами России, а Vercel и Supabase
находятся за рубежом. Сайт-портфолио, который ничего не собирает, под этот запрет
не попадает вовсе. Полный юридический разбор, остатки рисков и черновики уведомлений
в Роскомнадзор — в [`docs/legal-review-ru.md`](./docs/legal-review-ru.md) и
[`docs/rkn-notifications.md`](./docs/rkn-notifications.md).

## Часть 6. Работа на своём компьютере

Нужны Node.js 20+ с [nodejs.org](https://nodejs.org) (кнопка LTS).

```bash
npm install
cp .env.example .env.local
```

В `.env.local` вставьте те же URL и ключ Supabase, плюс:

```
VITE_ADMIN_EMAIL=ваша-почта-администратора
VITE_DEV_REGION=global
```

- `VITE_DEV_REGION` — какая версия показывается локально: по умолчанию `ru`
  (российская, без формы), `global` — международная с формой. Вместо переменной
  можно открыть `http://localhost:5173/?region=global`.
- `VITE_ADMIN_PASSWORD` нужен **только** если Supabase не подключён (демо-набор):
  тогда локальный пароль берётся из него, а на Vercel — из серверной переменной
  `ADMIN_PASSWORD` (её не видно в браузере).

`npm run dev` поднимает `/api/region` прямо в dev-сервере с той же логикой,
что и на Vercel (по умолчанию регион `ru`, то есть блок «Соцсети» с ником
Telegram; `?region=global` покажет международную версию с иконками).

Запуск:

```bash
npm run dev
```

Откройте `http://localhost:5173`. Панель: `http://localhost:5173/admin`.

Вход в панель — почта и пароль пользователя Supabase (Часть 2, шаг 9): локальная
разработка использует ту же базу, поэтому и авторизация та же.

## Часть 6.1. Иконка приложения (PWA)

Иконка на домашнем экране телефона и на вкладке браузера собирается из исходника
`assets/led-pwa.icon` — это бандл **Icon Composer** из Xcode 26 (внутри `icon.json`
с градиентом и `Assets/` с логотипом).

Если иконку нужно поменять — положите новый `.icon` на то же место и выполните:

```bash
npm install --no-save sharp
node scripts/make-icons.mjs
```

Скрипт перезапишет в `public/`: `favicon.svg`, `favicon-16/32.png`,
`icon-192/512.png`, `icon-maskable-512.png` и `apple-touch-icon` (180 / 167 / 152).
Можно передать и обычную картинку: `node scripts/make-icons.mjs my-icon.png`.

Живые эффекты Apple (стекло, преломление, полупрозрачность) существуют только
внутри iOS — в PNG они не переносятся, поэтому в веб-иконку идёт статическая
основа: градиентный фон плюс белый знак.

> **iOS цепко кэширует иконку.** Если после обновления на домашнем экране висит
> старая картинка — удалите ярлык и добавьте сайт заново через «Поделиться» →
> «На экран Домой».

Иконка вкладки, загруженная в панели управления (вкладка «Баннер»), перекрывает
`favicon` — но не влияет на иконку приложения для iOS.

## Часть 7. Если что-то сломалось

**На компьютере одни карточки, на телефоне другие / старые**  
Раньше браузер хранил копию у себя. Теперь источник — только Supabase.

1. Ещё раз выполните весь `supabase/schema.sql` в SQL Editor.  
2. На **том компьютере, где сайт выглядит правильно**, откройте `https://ВАШ-САЙТ/admin`. Локальные карточки сами уйдут в базу (в шапке будет «опубликованы в базу»).  
3. На телефоне закройте вкладку сайта полностью и откройте адрес заново. Если видите старое — в Safari: «Поделиться → На экран „Домой“» не кэширует HTML, но обычная вкладка может; сделайте обновление страницы.  
4. На Vercel проверьте три переменные и нажмите **Redeploy**.

**Сайт пустой / старые карточки**  
Проверьте, что SQL из `schema.sql` выполнен и переменные Vercel совпадают с проектом Supabase. Сделайте Redeploy.

**Панель пишет «Неверная почта или пароль»**  
В Supabase: **Authentication → Users**. Пользователь должен существовать, а его
почта — быть подтверждённой (при создании ставьте **Auto Confirm User**).
Проверьте также, что `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` на Vercel
относятся к тому же проекту.

**Панель сохраняет, но изменения не появляются / ошибка «row-level security policy»**  
Запись в базу разрешена только авторизованному пользователю: войдите в панель
заново (кнопка **Выйти** → вход по почте и паролю Supabase). Если ошибка осталась —
значит `supabase/schema.sql` запускали старой версией: выполните файл целиком ещё раз
в SQL Editor.

**В блоке «Соцсети» ник вместо иконок**  
Сайт определил вас как посетителя из России (так задумано, см. Часть 4.1).
Чтобы увидеть международную версию, откройте сайт с `?region=global`
(или задайте `VITE_DEV_REGION=global` локально).

**Картинки не сохраняются**  
Файлы грузятся в Supabase Storage (корзина `media` из `schema.sql`): главный баннер — оригинальным размером до 2 МБ, картинки статей — до 900 px по ширине, остальные поля — до 1600 px по длинной стороне (см. «Что панель делает с загруженной картинкой»). Если SQL со Storage не запускали, сайт попытается записать картинку прямо в базу — тяжёлые фото при этом лучше уменьшать заранее.

**«Не удалось загрузить видео: mime type video/mp4 is not supported»**  
Корзина `media` в базе осталась со старым списком типов файлов и не пускает видео —
Supabase сверяет тип файла со списком буквально и отвечает ошибкой 415.

Сайт при этом не ломается: панель сама нарежет ролик на кадры и сохранит блок
как последовательность картинок (см. «Параллакс-видео в статье»). Но цельное
видео легче и качественнее, поэтому корзину лучше починить.

Панель показывает под полем «Видео» готовый запрос и кнопку
**Скопировать запрос**. Скопируйте его, откройте Supabase → **SQL Editor** →
**New query**, вставьте и нажмите **Run**. Запрос делает корзину публичной,
поднимает лимит файла до 50 МБ и разрешает любые картинки и видео
(`image/*`, `video/*`):

```sql
insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
values ('media', 'media', true, 52428800, array['image/*', 'video/*'])
on conflict (id) do update set
  public = true,
  file_size_limit = 52428800,
  allowed_mime_types = excluded.allowed_mime_types;
```

То же самое делает повторный запуск всего `supabase/schema.sql`. После этого
видео загружается сразу, перезапускать сайт или делать Redeploy не нужно.

Проверить, что корзина настроена правильно, можно так: **Storage** в меню
Supabase → корзина `media` → **Configuration**, либо запросом

```sql
select id, public, file_size_limit, allowed_mime_types from storage.buckets where id = 'media';
```

Ролик должен быть в MP4 (H.264) или WebM и весить до 50 МБ: AVI, MKV, WMV и
FLV браузеры не показывают, поэтому панель их не принимает — ни как видео,
ни как нарезку кадров.

Уже сохранённый блок с кадрами можно заменить обычным видео: после починки
корзины загрузите в то же поле ролик — кадры заменятся файлом.

**404 при обновлении страницы статьи**  
В проекте есть `vercel.json` с rewrite на `index.html`. Не удаляйте его.

**Сборка Vite ругается на TypeScript**  
Локально: `npm run build`. Пришлите текст ошибки.

## Безопасность (коротко)

- Анонимный ключ Supabase лежит во фронтенде — так задумано: он даёт только чтение.  
- Запись в таблицы и в корзину `media` разрешена лишь роли `authenticated`,
  то есть после входа в панель почтой и паролем пользователя Supabase
  (`supabase/schema.sql`, Часть 2 шаг 9). Раньше писать мог любой посетитель — это закрыто.  
- `ADMIN_PASSWORD` — серверная переменная (без `VITE_`), в браузер не попадает;
  нужна только как запасной вход, если сайт работает без Supabase.  
- `/api/admin-login` ограничен по числу попыток (8 за 10 минут с адреса),
  пароль сравнивается без раннего выхода по символам.  
- Заголовки безопасности (HSTS, `X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`, `Permissions-Policy`) заданы в `vercel.json`.
  `Content-Security-Policy` намеренно нет: блок «Embed code» вставляет произвольные
  iframe и скрипты сторонних сервисов, жёсткий CSP их сломает.  
- Кэширование там же: файлы из `/assets/` (у них хеш в имени) кэшируются на год
  как `immutable`, а все страницы и корневые файлы — `no-cache, no-store,
  must-revalidate`. Без этого SPA-маршруты вроде `/privacy` кэшируются на CDN,
  и после деплоя посетители видят старую версию сайта.  
- Персональные данные посетителей сайт не собирает вообще: форм нет, заявки идут
  через почтовый клиент и Telegram (Часть 4.1). Юридический разбор —
  [`docs/legal-review-ru.md`](./docs/legal-review-ru.md), черновики уведомлений
  в Роскомнадзор — [`docs/rkn-notifications.md`](./docs/rkn-notifications.md).
